## 📖 Documentation Conventions

### File Organization
- `getting-started/` - Tutorials and quick start guides
- `deployment/` - Deployment guides for various platforms
- `release/` - Release management and publishing guides
- `development/` - Technical and architecture documentation
- `reference/` - Reference materials and indexes

### Document Types
- **QUICKSTART_*.md** - Quick start guides (< 5 minutes)
- ***_GUIDE.md** - Comprehensive guides
- ***_QUICKREF.md** - Quick reference cards
- **ARCHITECTURE.md** - Technical architecture
- **README.md** - Directory overviews

## 🤝 Contributing to Documentation

When adding or updating documentation:
1. Place files in the appropriate subdirectory
2. Update this index (docs/README.md)
3. Update the main README.md if needed
4. Use clear, descriptive filenames
5. Include a table of contents for long documents
6. Link to related documents

## 📝 Documentation Standards

- Use Markdown formatting
- Include code examples where appropriate
- Add screenshots for UI-related docs
- Keep language clear and concise
- Test all commands and code samples
- Update related documents when making changes
